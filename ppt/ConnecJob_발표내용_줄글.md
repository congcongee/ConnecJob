# ConnecJob 발표 내용 정리 (줄글)

> personal_project(ConnecJob) 기준이며, 구성은 「ppt에 꼭 들어갈 내용.txt」의 5개 목차를 따랐습니다. 개인 프로젝트라 업무분담은 1인 전담으로 쓰고, 간트차트는 아래 7단계 일정으로 그리면 됩니다.

## 1. 프로젝트 소개

ConnecJob은 취업 준비생이 자신의 경험을 자유롭게 적기만 하면, 그 경험에 맞는 실제 채용공고를 추천하고, 부족한 역량을 채울 준비 로드맵과 공고 맞춤 자기소개서 초안까지 이어서 만들어 주는 AI 취업 매칭 서비스입니다. 기존 구인구직 사이트는 사용자가 직접 키워드로 공고를 찾아야 하고, 내가 그 공고에 맞는지, 무엇이 부족한지는 알려주지 않습니다. 특히 신입 지원자는 '내 경험이 어떤 직무와 연결되는지'부터 막막합니다. ConnecJob은 이 간극을 "경험 → 추천 → 보완 → 지원서"라는 하나의 흐름으로 연결하는 것을 목표로 했습니다.

프로젝트는 10월 21일부터 11월 19일까지 7단계로 진행했습니다. 1~3단계에서 공공·민간 데이터를 수집하고 전처리해 통합 공고 표와 기술·자격증 사전을 만들었고, 4단계에서 벡터DB 기반 추천과 로드맵, 자기소개서 생성·첨삭 모델을 개발했습니다. 5단계에서는 이를 Django 웹 서비스로 연동했고, 6단계에서 실제 구인구직 사이트처럼 쓸 수 있도록 화면을 다듬었으며, 7단계에서 데이터 보강과 배포, 발표 준비를 진행합니다.

개발 환경은 Python을 기반으로 pandas로 데이터를 처리하고, requests·BeautifulSoup·Selenium으로 수집했습니다. 추천과 생성에는 LangChain, Chroma 벡터DB, OpenAI의 text-embedding-3-large 임베딩과 gpt-4o-mini·gpt-4.1-mini 모델을 사용했고, 웹은 Django 5.2와 SQLite, Bootstrap으로 구현했으며 Git으로 버전을 관리했습니다.

전체 흐름은 다음과 같습니다. 사용자가 경험을 입력하면 이를 임베딩해 벡터DB에서 비슷한 공고를 찾고, 기술 충족률과 직무 일치도로 다시 순위를 매긴 뒤, LLM이 상위 공고를 한 번 더 적합·부적합으로 판정합니다. 추천된 공고들이 공통으로 요구하지만 사용자에게 없는 기술은 준비 로드맵으로 정리되고, 사용자가 공고를 고르면 해당 공고 본문과 실제 자소서 문항을 바탕으로 초안을 만든 뒤 검수 LLM이 근거 없는 표현을 걸러냅니다.

## 2. 데이터 수집 및 분석

데이터는 총 15개 출처에서 모았습니다. 공고 데이터로는 서울 열린데이터광장의 서울시 일자리포털 채용정보 API(약 3만 9천 건), 인사혁신처 나라일터 공공채용정보(약 1만 9천 건), 잡알리오 공공기관 채용공시 API(527건), 그리고 robots.txt와 이용약관을 확인한 뒤 수집한 인크루트(482건)와 잡다(60건) 민간 공고가 있으며, 이를 하나로 합친 통합 공고 표는 60,100건입니다. 이 밖에 직무 이해를 위해 NCS 능력단위 13,442개와 능력단위별 자격종목, 고용24 직무데이터사전, 구인표준직무기술서 2,480건을 활용했고, 기업 규모 판별을 위해 공정위 대규모기업집단 소속회사(3,539개), 외국인투자기업(약 2만 개), 국민연금 가입 사업장(약 5만 3천 개)을 사용했습니다. 자기소개서 생성을 위해서는 하이잡의 기업별 자소서 문항 약 3만 4천 건을 모았습니다.

전처리는 출처마다 다른 열을 공통 열(제목, 기업명, 직무 분류, 기업규모, 지역, 경력, 마감일, 본문)로 맞추는 데 집중했습니다. 날짜는 날짜형으로, 금액은 숫자형으로 바꾸고, 문자 결측치는 '정보없음'으로 채우며 결측 여부를 따로 표시했습니다. 경력 조건은 신입·경력·관계없음 세 가지로 통일했고, 민간 공고 본문에 있는 이메일과 전화번호는 개인정보 보호를 위해 마스킹했습니다.

분석 과정에서 얻은 인사이트도 있습니다. 첫째, 공고에 적힌 기술 이름이 제각각이라(예: 'SK'와 '에스케이', 'Python'과 '파이썬') 기술명 통일 사전 175개, 자격증 사전 57개, 직무묶음 사전 212개를 직접 만들어 공고마다 기술·자격증 태그를 붙였습니다. 둘째, 공고에는 기업 규모 정보가 거의 없어서, 기업명을 정규화한 뒤 공정위 대기업집단 목록, 외국인투자기업 목록, 국민연금 가입자 수(300명 이상은 중견으로 근사)를 차례로 대조해 대기업집단·외국계·중견·중소 태그를 붙였습니다. 그 결과 전체 공고는 중소·기타 약 3만 7천 건, 공공기관 약 2만 건, 중견 1,633건, 대기업집단 520건, 외국계 129건으로 분포했습니다. 셋째, 경력 조건을 보면 '신입'으로 명시된 공고는 3,455건뿐이고 '관계없음'이 2만 7천 건으로 가장 많아, 신입 지원자에게는 '지원 가능한 공고만 거르는 필터'가 꼭 필요하다는 점을 확인했습니다. 마지막으로 직무명과 NCS 능력단위는 TF-IDF 글자 n-gram 유사도로 연결해, 공고가 어떤 표준 직무에 해당하는지 알 수 있게 했습니다.

## 3. 모델 개발

추천 모델은 공고 1건을 하나의 문서로 벡터DB에 저장하고, 사용자 경험과의 임베딩 유사도로 후보를 찾는 RAG 구조입니다. 공고 본문을 그대로 임베딩하면 근무조건·전형절차·회사소개 같은 문장이 잡음이 되므로, 이런 섹션을 걷어내고 업무와 자격요건 중심의 글만 임베딩했습니다. 그 결과 실제 공고 상위 10개 적합률이 52%에서 59%로 올랐습니다. 공고 길이는 중앙값 659자로 짧고 추천 단위도 공고이기 때문에, 청킹은 하지 않는 것으로 결정했습니다.

최종 점수는 "임베딩 유사도 + 기술 충족률 × 0.1 + 직무묶음 일치 × 0.05"로 계산합니다. 경험 20개와 공고 110개로 만든 평가셋에서 유사도만 쓸 때 재현율@10이 0.74였는데, 이 재순위를 더하자 0.79로 올랐습니다. 여러 대안도 실험했습니다. 경력 조건을 감점으로 넣으면 재현율이 0.48로 떨어졌고, 최소 점수 컷을 두면 0.59~0.70으로 오히려 정답이 잘려 나가서 둘 다 채택하지 않았습니다. 대신 경력은 검색 단계의 필터로 처리했습니다. 신입 필터를 적용하기 전에는 상위 10개 중 66%가 경력직 공고였지만, 필터를 적용한 뒤 지원 가능한 정답 재현율이 0.72에서 0.89로 올랐습니다.

여기에 LLM 재판정을 더했습니다. 점수 상위 20개 공고를 gpt-4o-mini가 적합·부적합과 이유로 판정하게 했더니, 실제 공고 적합률이 72%에서 94%(125건 중 117건)로 크게 올랐습니다. 처음에는 기술 스택이 조금만 달라도 떨어뜨려 추천이 2개만 나오는 문제가 있었는데, '직무 종류가 같으면 적합'이라는 기준을 프롬프트에 명시해 해결했습니다.

준비 로드맵은 관심 직무 공고들이 많이 요구하지만 사용자에게 없는 기술과 자격증을 요구 비율 순으로 뽑고, LLM이 기술별 공부 방법과 미니 프로젝트를 제안합니다. 자기소개서는 gpt-4.1-mini가 공고 본문, 사용자 경험, 해당 회사의 실제 자소서 문항을 받아 초안을 쓰고, 문단마다 근거가 된 경험 번호를 표시합니다. 그다음 검수 LLM이 경험 원문과 대조해 지어낸 표현을 찾아 한 번 더 고쳐 쓰고, 그래도 남은 표현은 '확인 필요'로 표시합니다. 실제로 경험에 없던 '배치→실시간 전환'이나 '협업·채널 운영' 같은 표현이 검수 단계에서 걸러졌습니다.

## 4. 웹 서비스 구현

웹 서비스는 Django로 구현했으며, 사용자는 회원가입 없이도 바로 이용할 수 있습니다. 홈 화면에서는 "MATCH YOUR JOB" 슬로건과 함께 경험을 적는 칸이 있고, 추천 결과 예시와 '이런 공고가 추천돼요' 카드를 기업 규모별로 미리 볼 수 있습니다. 마감 임박 공고와 직무별 공고 목록도 함께 보여 줘 일반 구인구직 사이트처럼 둘러볼 수 있습니다.

공고 둘러보기 화면에서는 검색어와 직무·기업규모·신입 여부로 공고를 거르고 마감이 빠른 순으로 정렬해 볼 수 있으며, 공고 상세 화면에서는 요약 표, 요구 기술, 직무 설명, 본문, 원문 링크와 '이 공고로 추천받기' 버튼을 제공합니다. 직무 알아보기 화면은 15개 직무의 하는 일, 맞는 사람, 대표 기술과 실제 공고에서 많이 요구하는 기술을 보여 주고, 13개 문장에 체크하면 나에게 맞는 직무를 1~3순위로 알려 줍니다.

핵심 기능인 맞춤 추천에서는 경험을 입력하면 추천 공고, 부족 역량, 준비 로드맵이 한 화면에 나오고, 원하는 공고를 골라 자기소개서 초안과 첨삭 결과를 받을 수 있습니다. 비회원의 결과는 해당 브라우저에서만 보이고, 로그인하면 계정으로 옮겨져 '지난 결과'에서 다시 볼 수 있으며, 다른 사람의 결과는 볼 수 없습니다.

To-be 시나리오로 정리하면 다음과 같습니다. 컴퓨터공학을 전공한 신입 지원자 A씨는 "파이썬으로 수업 과제 크롤러를 만들고, 동아리에서 데이터 분석 프로젝트를 했다"고 적습니다. ConnecJob은 무신사 Product Data Analyst, CJ제일제당 Data Analytics Engineer, 이노션 데이터 분석 및 컨설팅(Junior) 공고 3건을 추천하고, LLM이 공고마다 "지원자의 데이터 분석 경험과 관련이 있음"이라는 이유를 붙여 줍니다. 이어서 관심 직무인 데이터 분석·사이언스 공고 61건을 살펴, A씨에게 없는 기술 중 SQL(38%, 23건)과 Excel(20%, 12건)이 가장 많이 요구된다는 점과 추천 자격증 1순위인 정보처리기사를 보여 줍니다. 로드맵은 "뉴스 크롤러로 모은 데이터를 SQL DB에 저장하고 키워드별 기사 수를 분석하는 쿼리 작성하기"처럼 A씨의 경험을 이어 가는 미니 프로젝트를 제안합니다. A씨가 마음에 드는 공고를 고르면, 그 회사의 실제 자소서 문항에 맞춘 초안이 A씨의 경험만을 근거로 작성됩니다.

## 5. 프로젝트 결론

ConnecJob은 6만 건이 넘는 공공·민간 공고와 NCS, 기업 정보를 하나로 묶고, 임베딩 검색과 규칙 기반 재순위, LLM 재판정을 결합해 추천 적합률을 94%까지 끌어올렸습니다. 또한 추천에서 끝나지 않고 부족 역량 분석과 자기소개서 작성까지 이어지는 흐름을 웹 서비스로 완성했습니다. 화면 흐름 테스트 17개가 모두 통과했으며, PC와 모바일 화면 모두에서 정상적으로 동작하는 것을 확인했습니다.

이 프로젝트에서 얻은 시사점은 세 가지입니다. 첫째, 모델 성능 못지않게 데이터 정제와 사전 구축이 추천 품질을 좌우했습니다. 둘째, 점수에 모든 조건을 섞기보다 경력 같은 '지원 가능 여부'는 필터로 분리하는 편이 훨씬 효과적이었습니다. 셋째, 생성형 AI를 취업 서류에 쓸 때는 지어낸 내용을 막는 검수 단계가 필수적이었습니다.

한계도 있습니다. 벡터DB에 들어간 직무 공고 중 대기업과 외국계 공고가 적어 기업규모 필터의 효과는 검증하지 못했고, 중견기업은 공식 목록 대신 국민연금 가입자 수로 근사했습니다. 직무 연결에 쓴 글자 유사도는 뜻은 같지만 표현이 다른 직무를 놓치기도 합니다. 향후에는 공공 API로 공고를 더 모아 데이터를 넓히고, 직무 연결을 임베딩 모델로 바꾸며, 서비스를 배포해 실제 사용자 피드백으로 추천 기준을 다듬을 계획입니다.

참고 자료로는 서울 열린데이터광장, 고용24 Open API, 공공데이터포털(한국고용정보원·한국산업인력공단·국민연금공단·인사혁신처·공정거래위원회·산업통상부), 잡알리오 Open API, 하이잡, 인크루트, 잡다를 사용했습니다.
